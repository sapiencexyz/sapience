# GraphQL API

## Sandbox

Explore the API and discover available queries, mutations, and types in the interactive sandbox: **[api.sapience.xyz/graphql](https://api.sapience.xyz/graphql)**

The sandbox includes full schema documentation, autocomplete, and lets you run queries directly in your browser.

## Endpoint

```
https://api.sapience.xyz/graphql
```

## TypeScript types

The SDK exports all GraphQL types for use in your TypeScript projects:

```typescript
import type {
  Category,
  Question,
  Condition,
} from '@sapience/sdk/types/graphql';
```

View the full type definitions on GitHub: [packages/sdk/types/graphql.ts](https://github.com/sapiencexyz/sapience/blob/main/packages/sdk/types/graphql.ts).

## Quick example

```typescript
import { ApolloClient, InMemoryCache, gql } from '@apollo/client';

const client = new ApolloClient({
  uri: 'https://api.sapience.xyz/graphql',
  cache: new InMemoryCache(),
});

const { data } = await client.query({
  query: gql`
    query Questions {
      questionsConnection(first: 10, sortField: endTime, sortDirection: desc) {
        items {
          questionType
          predictionCount
          condition {
            id
            endTime
          }
          group {
            id
          }
        }
        hasMore
      }
    }
  `,
});

console.log(data.questionsConnection.nodes);
```

## Notes

- The API is currently public; please be considerate and cache when possible.
- Use `slug` (not `id`) when you need a stable, human-friendly identifier — most ID fields on Sapience entities are `Int!` and shift between environments.
- Prefer the `*Page` queries (`questionsConnection`, `conditionsConnection`, `conditionGroupsConnection`, `categoriesPage`, `predictionsPage`, `positionsPage`, etc.) for list reads. They take flat `take`/`skip` args plus a purpose-built filter input, and they return a `{ items, hasMore, totalCount }` envelope you can paginate against without inspecting `items.length`. The bare-array equivalents (`questions`, `conditions`, …) still respond but are `@deprecated` and will be removed.
- Some queries are marked `@deprecated` in the schema (`claims`, `closes`, `conditionGroup`, `pickConfiguration`, `tradeCount`, `users`, plus the bare-array list queries listed above). They still respond, but rely on them at your own risk — read the schema before depending on one.
